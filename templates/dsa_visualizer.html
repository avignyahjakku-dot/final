DSA Complexity & Campus Application Summary

Theoretical and practical justification for every Data Structure and Algorithm implemented in this project.

Algorithm / Data Structure Best Case Time Average Case Time Worst Case Time Space Complexity Campus Application in this Project
Arrays O(1) (index) O(n) (lookup) O(n) O(n) Stores item records retrieved from MySQL; foundation for sorting and search algorithms.
Linear Search O(1) O(n) O(n) O(1) Scans item names, descriptions, categories, and campus locations without requiring sorted order.
Binary Search O(1) O(log n) O(log n) O(1) High-speed report retrieval by numerical Item ID after sorting the records.
Bubble Sort O(n) (optimized) O(n²) O(n²) O(1) Sorts campus reports alphabetically or by date; simple adjacent swapping logic.
Insertion Sort O(n) O(n²) O(n²) O(1) Efficient when new reports are appended continuously throughout the day into an existing list.
Selection Sort O(n²) O(n²) O(n²) O(1) Minimizes memory writes (guarantees at most O(n) swaps).
Singly Linked List O(1) (head insert) O(n) (traversal) O(n) O(n) Maintains 'Recently Reported Items' feed dynamically with instantaneous head insertion.
Binary Search Tree (BST) O(log n) O(log n) O(n) O(n) Indexes all campus items by ID; Inorder Traversal outputs sorted reports in linear time.
